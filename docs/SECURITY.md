# Security model

AEERAL DEV will execute code generated by an AI model. Treat every generated file, command, repository instruction, and external response as untrusted input.

## Mandatory boundaries
- Do not run generated commands on the API host.
- Execute project code only in disposable, isolated containers with CPU, memory, process, disk, and wall-clock limits.
- Default to no network access from execution containers. Add narrowly scoped access only when explicitly required.
- Never mount host credentials, Docker sockets, SSH keys, or cloud metadata endpoints into a task container.
- Keep provider credentials in server-side secret storage; never return them to the model or browser.
- Require explicit human approval before production deployment, destructive data changes, permission changes, or paid operations.
- Validate every model-produced action against a strict schema and an allowlist.
- Record task state transitions and tool invocations without logging secrets.

## Initial implementation status
The current API is task-intake scaffolding only. It does not execute shell commands, modify repositories, call an LLM, or deploy software. Do not expose it publicly without authentication and rate limiting.
